## 2.1.37 — Performance, stability and updater reliability

Session history now reads journals in bounded blocks, reducing temporary allocation and main-thread stalls while preserving canonical message revisions, UTF-8, chronology and damaged-line recovery. Search ranks title matches before text and excludes stale indexes during rebuilds. Files recovers lost watchers and rejects late validations from older project selections. Unowned synthetic pointer releases no longer throw in the chat reader.

The double-click updater recovers from GitHub API 403/429 using the public stable-release redirect. It accepts only HTTPS on this exact fork with a stable version tag, then downloads the installer and SHA-256 checksums for that resolved tag. Other API failures remain visible. The separate pinned PowerShell updater defaults to 2.1.37 and retains its exact-version throttling recovery.

Windows x64 only. App and extension are 2.1.37; protocol remains 14. Cyberpunk, native attachments, unchanged-draft Core fallback, execution protections, Temporary Chat and durable Goal/Loop behavior are preserved. Known Goal cross-ledger publication gaps remain documented; this release does not claim to resolve them.

A synthetic 41.5 MB journal took about 25% less time to read in the reviewed candidate, with less post-call heap allocation. This is an isolated measurement, not an app-wide speed or memory guarantee. Candidate Windows CI passed 7,928 main tests, 28 serial tests, six live plugin tests and 42 active UI checks; existing exclusions and retries are recorded in the audit. Release verification is performed again at the release commit, and packaging/public artifact checks are separate gates.

No installed user data or signed-in provider was accessed for this Git-only work. User configuration, credentials, sessions and plugins are retained by the update path. See docs/worklogs/performance-stability-2026-10-06.md for scope and measurement limits.
