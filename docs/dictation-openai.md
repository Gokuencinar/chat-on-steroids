# Dictation providers in Chat On Steroids

## ChatGPT microphone versus OpenAI API

CoS 2.1.43 has three explicit options in the composer. **Windows dictation (local)** listens via the installed Windows recognizer and writes editable speech text directly into the unsent CoS draft without requiring an OpenAI API subscription. **ChatGPT microphone (browser)** opens the selected ChatGPT conversation in the signed-in browser (or ChatGPT for a new conversation). The user must click the browser page's microphone there and satisfy the relevant browser/Windows mic permission when prompted; the transcript is editable and stays in the *browser's ChatGPT draft*, not automatically in CoS's desktop draft. In CoS's built-in browser, the isolated ChatGPT partition is now allowed microphone **audio only for the exact https://chatgpt.com origin**; video, other origins and the default app/extension partitions remain denied. CoS does not extract ChatGPT browser cookies, browser-recorded audio, private endpoints, or hidden subscription APIs. **OpenAI transcription (cloud)** is a third, explicitly selected, separately billed OpenAI API workflow that can place the final transcript in the CoS draft, subject to the API account's quota and the existing recording limits. Neither CoS nor a ChatGPT subscription can grant extra OpenAI API credits or bypass usage limits.

A genuine OpenAI API HTTP **429** is now classified from documented `error.code` / `error.type` values: prepaid credits exhausted, project/organization spend limits, organization usage limits, temporary API rate limit, and unknown quota. Returned free-form API error text is not displayed or logged. Insufficient credits and spend limits cannot be fixed with retry loops; review API billing or use Windows local/ChatGPT browser microphone. A temporary rate limit may clear after the provider's cooldown. This classification is covered with mock responses; it does not claim a live API account has any available balance.

The **Windows (local)** microphone mode retains the existing Windows System.Speech recognizer and its offline text/partial events. The separate **OpenAI transcription (cloud)** option is opt-in and records only when the user clicks the microphone. Recording is limited to **45 seconds / 8 MiB**. The recording is uploaded on the user's Stop action **or automatically at the 45-second limit**, as disclosed in the recording UI, to the official OpenAI API at https://api.openai.com/v1/audio/transcriptions with model **gpt-transcribe**, recommended in the [file transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text). An unexpected MediaRecorder stop caused by a lost device, revoked permission or ended MediaStream is **not** upload authorization: CoS discards its chunks locally and reports that no audio was sent. Only the final returned text enters the current unsent draft. CoS never auto-submits the prompt.

**Privacy and billing:** Cloud mode transfers microphone audio to OpenAI; this is distinct from ChatGPT voice and can incur API usage charges. CoS does not reuse a ChatGPT cookie, subscription credential or private endpoint. The existing Setup OpenAI API key for the active profile is retrieved inside main using getSecret(setupApiKeySlot(getConfig().tunnel.profileId)); the key must already be securely stored and never reaches the renderer. No recording, key, HTTP error body, or other audio payload is written to disk/logs by this feature. Cloud mode must be explicitly selected; Windows remains the default.

**Security:** The renderer acquires microphone access only after a user click. The main process validates renderer ownership and input type, MIME, duration and byte bounds. Only one transcription at a time is allowed. Cancelled/destroyed-window requests abort the network fetch. Changing drafts, manually typing, pressing Escape, navigating, hiding or unloading discards outstanding audio and results. Responses are bounded; HTTP errors become fixed messages without server-provided bodies. Electron must grant microphone media permission **only** to the trusted CoS renderer. Browser/web origins must not gain any additional permission.

## IPC integration owned by the main agent

Registration is in registerDictationIpc in src/main/dictation.ts. Existing Windows dictation:start, dictation:stop and dictation:event are unchanged. Add these narrowly exposed preload methods:

| Preload name | Main IPC channel | Response |
| --- | --- | --- |
| dictationOpenAIKeyStatus() | dictation:keyStatus | { ok: true, data: { available: boolean } } |
| transcribeDictationAudio({ audio: Uint8Array, mimeType, durationMs }) | dictation:transcribe | { ok: true, data: { text: string } } or { ok: false, error } |
| cancelDictationTranscription() | dictation:cancelTranscription | { ok: true, data: undefined } |

Allowed MIME types are audio/webm, audio/ogg and audio/mp4; durationMs is a positive integer not exceeding 45,000. Keep the audio as a Uint8Array in Electron IPC; do not JSON-stringify/base64 the recording. No unrestricted fetch, arbitrary IPC channel, secure secret read or external URL should be exposed to the renderer. A compatibility guard preserves Windows dictation until the new preload methods are present. The trusted app's permission request/check handlers must narrowly grant audio capture (and no video) for the actual CoS window.

**Cross-context troubleshooting:** Electron's renderer, isolated preload and main process have distinct JavaScript realms. The main handler accepts a real one-byte Uint8Array view using a realm-independent validation and copies it before awaiting credentials. Do not validate the IPC payload solely with the main realm's `instanceof Uint8Array`: legitimate microphone bytes from another realm can then fail with `Invalid or oversized microphone recording`. Ordinary arrays, `DataView`, untyped objects and oversized views remain forbidden. Completed/cancelled upload requests also release their window-destruction listener so repeated dictations do not accumulate listeners.

If cloud dictation fails, identify the **phase** without logging private audio or API keys: a message about setting an OpenAI API key occurs before microphone capture and means a separate API credential for the active CoS Setup profile is unavailable (ChatGPT Plus/Pro access is not an API key). A microphone permission error occurs before recording and must be checked against the trusted renderer's Electron audio-only permission policy. `Invalid or oversized microphone recording` occurs at the IPC validation boundary, before any network request. An OpenAI quota, authentication or network error occurs only after Stop, during the official API request. Tests for the main handler use mocked IPC and HTTP rather than a production microphone or paid transcription; they do **not** establish a complete installed-Electron reproduction.

Unit tests mock the network or recorder. No real microphone capture, API charges or live calls are attempted without a user-supplied key.
